### P7′. 必填字段用 `[]` 不用 `.get()`（Boss 定，替换原 P7）
> **字段不存在就让它崩 —— 响的失败好过安静的零。**
> 读必填字段时**把读取路径记进日志**（形如 `results[].shaMatchesBaseline`），辅助发现「键名存在但层级/含义不对」。

**根因不是「忘了先看键名」，是 Python 的 `.get()` 在字段不存在时返回 `None`，而 `None` 会在下游被当成合法值继续算下去。** 今天四次全部可归到这一个方法选择：

| 写法 | 读到的 | 结果 |
|---|---|---|
| `it.get('shaGatePassed', …)` | `None` | 「全 16 失败」假象 |
| `it.get('ok', it.get('match'))` | `None` | 「全 16 失败」假象 |
| `r.get('class')` → `r.get('kept')` | `None` | 「判定后剩 0 行」 |
| **`d['scenes']`** | — | **KeyError —— 这四次里唯一一次「响了的失败」** |

**主防线就是上面那条禁令，不需要 API 仪式。**（曾提议「要求调用方先说出键名」，Boss 否掉：把一个 stdlib 方法选择问题变成要维护的调用约定，而**约定会腐坏，禁令也会，但禁令不需要新代码**。）

⚠️ **残留缺口（诚实承认，不假装堵上）**：该禁令抓住「键名不存在」，**抓不住「键名存在但层级/含义不对」**（例：顶层确有 `shaGatePassed`，但它是聚合数而非逐场景值）。日志记读取路径是**辅助**，不是主防线。

### P7″. 聚合前先断言输入集合非空并打印大小（Boss 定）
> **`any()` 覆盖零个元素返回 `False`，与「真的没有」完全无法区分。**

| 写法 | 空输入时返回 | 后果 |
|---|---|---|
| `d.get("k")` | `None` | 被当成合法值继续算 |
| `any(cond for x in 空集合)` | **`False`** | **空真；语义上完全合理的布尔值，更危险** |

**空集合上的聚合结论没有证据资格，哪怕它与另一次非空运行碰巧一致。**
实例（lead-2 自报）：首次校验逐区域天花板时按 key 名过滤（`'ceil' in k or 'after' in k`），真实字段是 `sim_per_tile_const` ⇒ **过滤未匹配任何字段，仍返回「无场景 ≥0.99 = False」**。第二次以正确字段复算，结论仍是 False。**两个数一致，但第一个不具备证据资格。**
> **在这个项目里，防御规则只有两种命运：写成机制的那活下来，写成提醒的那腐坏成建议。**

- **P1 活下来的原因**：它是结构性的 —— measure 阶段物理上读不到不存在的文件，拿掉输入它 `exit=2` 拒绝。
- **原 P7 腐坏的原因**：它还是散文，而散文正在输给习惯。**Boss 承认那条规则是他自己那个病的实例** —— 上一轮刚裁定「披露不能替代修复」，转头就给 P7 写了一条散文提醒。**提醒就是披露的另一种写法。**

**判断一条新规则该怎么写的唯一标准：它能不能被做成「坏状态物理上不可能」？**
**能 ⇒ 做成机制。不能 ⇒ 老实标成「这是一条需要人记得的规矩」，别假装它是防线。**

### P10. 结论性表态的适用条件：阳性对照通过（Boss 定，替换旧措辞）
> **三选一 / 任何结论性表态的适用条件：阳性对照通过。**
> 对照未过时的正确产出是「**未测**」，不是「视情况」，更不是任选其一。
> **`未测` ≠ `已测得分散`** —— 前者是「没做成」，后者是「做成了，结论是分散」。**这两句必须逐字分开写。**

**为什么旧措辞危险**：「不许视情况而定」把「不做判断」与「不做区分」混成一件事，于是「不许逃避」被执行成了「不许在无效数据上表态」—— **方向对了，射程却覆盖了不该覆盖的地方。**
**正确写法是给禁令加前提，而不是加大压力。**
陷阱成因由 lead-2 与 Boss 各担一半（lead-2 加的「照实选」被读粗成「无论如何挑一个」）—— 主动把自己写过的约束列为可能有害的东西，优于被别人指出来。

### P11. manifest bbox 不一致 = 纯记录问题（已关闭）
`similarityNormalized(rgbaOld, rgbaNew)` 比的是**整张画布解码后的像素**；manifest 的 `bbox` / `scale` / `pixelWidth` / `pixelHeight` **只进报告结构，不参与比较区域构造**；`gatePassed` 的失败信息 "the full canvas WAS compared" 与此一致。
⇒ 那 5 张「bbox × scale ≠ pixelWidth/Height」的基线**只是记录元数据问题，不影响任何相似度读数**。**此线关闭。**
### P12. 「不许重试」≠「不许换输入」（Boss 定，v4 条款精确化）
> **禁止：在既有失败输入上调阈值、按失败样本挑输入。**
> **允许：更换为性质不同的新输入实例。**

**混成一条会禁止掉唯一正确的做法。** 把同一个失败输入放大到刚好越线 = 拟合；换一个本质上更难的新输入 = **建立仪器属性**。
**敏感性对照要选「最坏情况」而不是「最接近真实」**：目的是让编解码产生一个尺子必然看得见的差异。
实例（任务九）：① 白噪声/随机噪声图（JPEG 经典最坏情况，高频全在高频 DCT 系数）→ ② 块边界对齐的高对比硬边（周期严格 = 8 或 16）→ ③ 纯色大面积 + 一条高对比细线（验证**局部**灵敏度）。

### P13. 口径同一（reproducibility）与灵敏度（sensitivity）是两个独立性质
- **口径同一**：复现 harness 已提交的读数（实例：逐位复现 `go_sim`，16 场景 max delta = 0.000e+00）⇒ 度量与 harness 一致。
- **灵敏度**：对目标现象**有响应** ⇒ 尺子看得见它。

**两者不是替代关系。** 用前者顶替后者 = 丢失一条证明力而记录里看不出来。
⚠️ **两个量级探针若走同一编码器路径，只证明量级，不证明灵敏度。**

### P14. 已过线 / 已满足条件的场景不得进入「结构性不可达」判定
`calendar`/`state` 已过门禁 ⇒ `gap` 为负 ⇒ `deficit >= gap` **平凡成立**。**把已过线场景称作「结构性不可达」是范畴错误。**
**校验式「判定之和 == N」仍须成立** —— 改为对 N 个场景各给**互斥且穷尽**的判定（过线场景单独一档，或明确标「不适用本判定」并单独计数），**不许靠排除少数场景来凑和**。

### P17. 稳定标识优先于漂亮标识（Boss 定）
> **已被引用的文档，编号与标题一经发布不再变更。**
> 发现不有序或不风格统一时，**加索引、加注、或统一「新增」部分的命名风格，不改旧号。**

**理由（两条）**：
1. **重编号打断的是别人已经建立的引用链** —— 综合报告已被多轮引用，`§7.2b` / `§7.6b` / `§7.6c` 在别处、在 wiki、在任务书里都被引过。**改号 = 让所有这些引用同时失效。**

⚠️ **引用链的断裂不会报错** —— 它表现为「查不到那一条」，**通常被读成「没记」**。与「内容缺失会报错、归属错误不会报错」（P16）同族。

### P18. 正则类比对必须带行锚定（Boss 定）
> **跨行匹配（`[^x]*`、`.` 未加 `s`/`m` 标志）在多数实现里默认可跨行**，因为字符类里没有排除换行。
> **它产生的是「少匹配」而不是「多匹配」，而少匹配会被读成「内容缺失」。**
> 凡用正则做「A 应有 N 条、B 实有 M 条」这类**双向核对**，**必须先用一条已知行验证它只匹配本行**（例如 `grep -c '^### ' file` 与 `grep -c '^###.*$' file` 必须相等）。
>
> ⚠️ **扩写（Boss 批，task12 现场补入）：匹配方向（跨行 / 单行 / 贪婪 / 懒惰）都会改变计数，凡用匹配做计数，该方向必须先在已知对象上自检。**
> **单行正则 vs 多行 CSS 块 ⇒ 同样少匹配。** task12 实测：扫描器报「Headhunt 有 **0** 条几何规则」，而 `render.go:548` 明确引用 `.lh{width:95px}` —— 真相是模板用**多行 CSS 块**（`.lh {` 一行、属性下一行）。修好后 **181 条规则**、`.lh` 在 **`Headhunt.tmpl:26`**。
> ⇒ **跨行与单行两个方向，都会把「我没找到」伪装成「它不存在」。**

**本项目已集齐四种形态（一个共同结构：工具正常返回、结论形态无误、对象是错的）**

| 形态 | 表现 |
|---|---|
| `d.get("k")` | 字段不存在 → `None` → 被当成合法值继续算 |
| `any(...)` | **空集合 → `False`**（空真，语义上完全合理，比 `None` 更危险） |
| `head` 截断 | 报「唯一性」而实际看到的是被截断的视图 |
| `[^>]*` 跨行 | 只捞到 3/13 条 → 差点报「索引漏了 10 个小节」，**而索引是对的** |
| **单行正则 vs 多行 CSS 块** | 报「Headhunt 有 **0** 条几何规则」→ **而 `render.go:548` 明确引用 `.lh{width:95px}`**（task12 实测） |

⚠️ **与 P16/P17 同族**：都是「用机械核对防止归属/内容出错」，**而核对本身会出错**。

### P26. 报「字节数」必须用 `os.path.getsize()` 或 `wc -c`（Boss 定）
> **`len(open(p, encoding=...).read())` 是字符数，不是字节数。**
> **文件含非 ASCII 时两者不等，必须给出换算链。**

**现场（Boss 的 391 vs Worker 的 417）**：`assets/css/common.css` 实测 `os.path.getsize()` = **417 字节**、CR 0、16 换行、14 非空行；而 `len(decoded str)` = **391 字符**。
**差值 26 = 13 × 2** —— 非 ASCII 字符 **13 个**（`稀/有/度/图/标/…`，均在 U+4E00–U+9FFF），**UTF-8 下每个汉字 3 字节，比 1 字符多 2 字节**。
**换算链：字符数 + 非 ASCII 字符数 × (单字符字节数 − 1) = 字节数**，即 `391 + 13 × 2 = 417` ✓。

⚠️ **这是量纲错，不是四则运算错** —— 与本项目栽过两次的那一族同源（3 通道 vs 4 通道分母、`descent` 负值按正值参与计算）。
**结论保留、数字更正、两个数并存不抹平**（P24）：Boss 的**结论**仍成立（`position:`/`left`/`top` 各 **0 次**，共享样式表无位置声明，**补扫不改变任何计数**），只是那个字节数报错了。

### P19. 序关系对照：特征设计必须自带一条（Boss 定）
> **凡设计特征，除「应当检出」的正向对照外，必须至少有一条「序关系 / 单调性 / 边界情形」对照，且该对照不含阈值、不含预登记量级，只断言性质的相对次序。**

**理由：阈值类对照可以被调参数救活，序关系类对照不能。** 后者是唯一能在不改尺子的情况下否证特征的对照。
三种最省的形式：**单调性**（量↑ ⇒ 特征↑）、**边界**（空输入 ⇒ 特征归零）、**对称**（交换两个对称输入 ⇒ 特征不变）。
**实例**：PC4（SW(1px)=2.98 > SW(4px)=2.00，方向反了）—— **你在别的对照都在调阈值时，它直接把基质错误顶了出来。**
⚠️ **代价**：设计期断言**只覆盖你设计时想到的错误类别**（本轮漏了基质类）。⇒ **P19 不是免疫，是补网。**

### P19′. 序关系对照必须**前置到设计第一步**（Boss 定）
> **P19 的对照必须先于任何阈值的写出；若顺序反了，即使对照齐全也按未执行处理。**

**理由**：它是唯一一类「**不需要先知道正确答案长什么样**」的对照 —— 正向对照要先有期望值，序关系对照只需要一条事实（「厚线更宽」）。
⇒ **它不是对照集里的一项，是设计任何特征的第一步。**
本轮它虽然存在，却因为写在后面、且其它对照在调阈值，**没能最早报警** —— **那是位置问题，不是它的问题。**

### P20. 失败先归因到「机理读错了」，再考虑换仪器或调阈值（Boss 定）
> **任何仪器/特征失败，先归因到「机理读错了」，再考虑换仪器或调阈值。**
> **机械判据：问「我对这个对象机理的陈述是哪来的」** —— 来自推导链（`derived`）、还是来自直觉（`assumed`）。**每一项标了 `assumed` 的，先证它；证不出来就是它错。**

**理由（来自跨轮死因归并）**：本项目至今以「未测」收尾的三轮，症状分两类而**根只有一个**：

| 轮 | 症状 | 根 |
|---|---|---|
| 任务八分层失败 | 基质 | **机理没读对就动手** |
| 任务十分层失败 | 基质 | 同上 |
| 任务九对照全败 | 灵敏度 | 同上（4:2:0 而非 AC 量化主导；周期 8 是 DCT bin 1 非最高频；把上界当期望） |

**任务九那三次失败没有一次是尺子的问题。** 所以「基质选错」与「灵敏度不成立」是同一根的两副面孔，**而「换基质 / 调阈值」两种反应都治不了根** —— 它们各自绕过了「机理对不对」这个唯一该问的问题。

### P21. 「已修改」与「已验证」是两件事（Boss 定）
> **一处修改在「新数据」上跑过一次之前，记为「已改、未实测」。**

⚠️ **尤其当它的效果方向是「不再给出结果」时** —— 那意味着它修改后与未修改时**长得一模一样**，**而「沉默」本身是它最容易被误认为「正常」的状态**。

**当前适用**：B 类洞检测器（`平坦 ⇒ 沉默` 前提已修）**从未在新洞假设上跑过** ⇒ **其「沉默」目前只有构造性保证、没有实测**。措辞按「已改、未实测」记。
**重跑的意义不是找洞，是分清「它检查过、确实没有」与「它没有发言权」** —— 这两句在报告里现在长得一模一样。

### P22. 反向裁定时的清点义务与在飞禁令（Boss 定，两半）
> **（执行侧）**收到反向裁定后，**第一动作不是执行，而是清点「有没有已发出的指令依赖旧判断」**，并把**清点结果与当前状态一并发出**。
> **（决策侧）**不得在某个动作**在飞**的时候连续发出一条「停 X」和一条「恢复 X」** —— 那不是修正，是把修正的**成本转嫁给执行者**。要改就在**同一条消息**里写全：**旧裁定作废 / 新裁定 / 当前在飞的是谁 / 它该做什么**。

**成本可见优于成本消失**：本轮 Boss 连续两条反向裁定，worker-4 收到一条基于已作废判断的停工指令。**第一时间的动作是发更正 + 写明「责任在我不在执行」+ 让它说明是否丢了东西** —— 第三步是关键，它让代价浮出水面，而不是被「重新做一遍」吸收。
**实际代价为零**：worker-4 回报「什么都没丢弃，仪器已在盘上且 PC0 已作前置条件，gg 探针只读无产物」。

⚠️ **这条族的新成员：错的不是尺子，是决策的时序。** 我手里那条消息**发出时是真的，只是发出前世界变了** —— 与 P18 同族（工具正常返回、结论形态无误、对象已错），**但补法不同**：不是加自检，而是**发指令前确认它不会被随后的消息作废**。

### P23. 机理陈述必须落盘（P20 的可执行形态，Boss 定）
> **每个特征动工前，必须往 `instrument.json` 写一行可证伪的机理陈述**，形如
> 「**X 类元素在残差中应表现为 Y；若不是，则机理错。**」
> **且对照集里必须包含至少一条「若该陈述为假则响」的控制。**
> **没有这条陈述或其反证控制 ⇒ 该特征不得进入对照阶段。**

**理由**：P20 说失败要先归因到机理，P19′ 说序关系对照要前置 —— **这一条把两者变成一个必须落盘的字段**。否则它们是两条提醒，**而提醒在本项目已被证明会腐坏**（P17 现场：P17 自己被 P16 逮住）。

**起因**：worker-4 目前是**自觉**在标 `derived`/`assumed`，而**自觉会衰减**。P20 立了但没有机械形态，P23 补上。
**task11 / task12 若已开工，此条从下一轮起强制**，不要求回头补。

### P24. 预登记必须绑「我在乎的量」，不是「我预测的失败方式」（Boss 定）
> **预登记的条件必须绑定「决策所依据的那个量」，不是「我预测它会以何种方式失败」。**
> 后者一预测错，**条款永不触发，而条款的存在会让人误以为风险已被覆盖。**

**检验问法：「若这条触发，我是否会做出不同决定？」**
- 答案是「**会**」⇒ 才值得预登记。
- 答案是「**不会**」（触发与否我都一样）⇒ **那它不是预登记，是安慰。**
