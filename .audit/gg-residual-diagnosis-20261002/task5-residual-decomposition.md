## 0. 直接回答 Boss 那一句

> **gg 的残差是「整块没画」还是「系统性偏差」，还是「弥散的内容不一致」？**

## 4. 三类的举证方式（凡否定性结论逐条填，空栏按未举证处理）

### A 类「系统性偏差」= 0 行 —— 举证方式
不是「我没看见」，是三条：
1. **穷举**：对 14 个场景各求一次全局单通道常数修正的最优解 `c*`（`c*_c = median(Δ_c)`，中位数口径已落盘），代入同一 4 通道分母重算 sim。全部 14 个天花板 < 0.99（§3 表，逐行可复算）。
2. **仪器自检**：同一口径在**已知系统性输入**上必须给出 ≥ 0.99 —— P1/P1b/P1c 三个对照全部给出 true（§2）。口径不是恒假的。
3. **下限对照**：修正确有正收益，最大 +0.04536（`help`），最小 +0.00000（`base`）。因此「A=0」的准确含义是**「没有单点全局修正能达标」**，不是「完全没有色偏」。

### B 类「整块没画」= 5 行 —— 举证方式
1. **仪器自检**：P3 在已知纯色缺口上 exact 命中；N2 在未改动渲染上 0 内洞。检测器不是恒真，也不是恒假。
2. **几何**：每个命中内洞的 tile box 与像素 box 已落盘（`tmp/residual/report.json` 的 `B_info.hits`），可逐个对照模板。
3. **佐证（`inferred`，用基线作比对参照）**：内洞内的 Σ|Δ| 占该场景总残差的比例 —— `enemy` **44.92%**（一个洞吃掉近一半残差）、`lottery` 31.85%、`box-detail` 20.25%、`operator` 20.37%、`base` 8.20%。

## 9. 下一步该做什么 —— 按「先算上限再投工时」，全部是**先量什么**，不是实现方案

**B 类（5 行，其中 3 行佐证强）**
- 先量：把 5 个内洞的 pixel box 画到图上，逐个对照对应 `.tmpl` 的**声明元素**（元素级映射），确认它对应哪个声明元素、是「元素没画」还是「画了但被同色块盖住」。
- 先量（便宜、能一次性解释多行）：`onerror` 回退触发率 —— 模板里远端 URL + `assets/common/amiya.png` 回退共 9/6/5 处（base/operator/box-detail），统计渲染时有多少张真的走了回退。
- **暂不动手**：`base` 一行佐证不支持（洞心两侧逐位相同），在人工复核前不投工时。

**A 类（0 行，但色偏成分真实存在）**
- 先量：把逐通道有符号中位数**拆到 tile 网格**，看 `help`(−44/−46/−47)、`enemy`(+23/+20/+17)、`depot`(+12/+32/+38)、`box-summary`(+19/+19/+19) 的偏置集中在哪些区域 —— 是背景色、边框色还是文字色。
- 为什么先量：即使把这一层全部修对，收益上限已被测死为 **+0.04536**，不足以跨线；知道它集中在哪，才能判断它是否与 B 类的整块缺口是**同一个成因的两面**（例如同一处背景没画，顺带造成大面积色偏）。**在 B 类定位完成前不要单独为色偏投工时。**

**C 类（9 行）**
- 先量：**按元素类型分层**分解残差（文字 / 图像 / 背景 / 边框），因为现在只知道整体弥散，不知道哪类元素贡献最多。这与 task4 的「误差集中度检查」同族，但换了一个分解轴（元素类型而非热区）。
- 极便宜的一手：跑**背景 oracle 天花板**（两侧平铺背景重绘后重算），AGENTS.md 已有先例，能一次性判断「背景层修法值不值得做」。

**跨三类的统一前置**
